## 執行與重現

在 `okx-monitor/backtest`，Python 3.12：

```bash
python -m pip install -r requirements.txt
python -m unittest discover -p 'test*.py' -v
# 首次使用公開 GET API 下載（無金鑰）
python -m v09 --cache research_v09_cache --output v09_run
# 精確重現交付研究：使用封存 OHLCV 及當時合約單位快照
mkdir -p research_v09_cache
tar -xzf v09/results/ohlcv.tar.gz -C research_v09_cache
python -m v09 --cache research_v09_cache --instrument-snapshot v09/results/coverage.json --output v09_reproduced
```

預設：2024-01-01 至 2026-01-01 UTC，12 個固定 USDT 永續合約，1H／4H／UTC 1D。這是固定籃子，不是全市場、市值前 200 或歷史上市全集。現在仍上市的合約有存活者偏差；下載失敗、缺棒、重複、未收盤資料、部分上市區間會明確失敗，整體回傳非零 exit code，不悄悄補值。`coverage.json` 保存精確資料 SHA-256 與合約規格快照。新下載可能遭交易所修正；請使用封存資料重現。`--fetch-only` 可只驗證資料。

`--symbols` 與 `--bars` 可縮小研究；切勿依結果挑幣後宣稱原始留出集仍未受污染。資料、參數、成本與選幣門檻均固定，所有情境均披露。每次執行輸出：

- `coverage.json`：36 組區間覆蓋、資料雜湊、合約單位／最小數量／價格跳動單位。
- `summary.json`：全部 126 情境（每週期 42），策略／資產／方向／年份／簡單趨勢市況分組統計、拒絕原因、風控與限制。
- `trades.jsonl.gz`、`equity.jsonl.gz`：每筆淨損益、淨 R、成本、持倉天數、分批成交，以及紙上資金曲線；各情境獨立，不能相加當成單一帳戶績效。
- `candidate_reports.jsonl.gz`：每筆探索性紙上進場的固定欄位報告；含成本、退出、配置、事件、風控與未驗證標籤。這些是歷史範例，非當下建議；無前瞻證據的歷史個案不會倒填後來的勝率。

## 方法與可信度

60 日暖機；訓練至 2025-04-07；14 日 embargo 後驗證 2025-04-21 至 08-19；再隔 14 日，保留測試 2025-09-02 至 2026-01-01。訊號在已完成棒產生、下一棒開盤進場。區間尾部平倉，不把未平倉持入下個樣本。沒有最佳化參數；walk-forward 是兩個依序前進的固定參數評估區塊，直接對應驗證與保留集，不能重複加總樣本，也不是每個視窗重新訓練的模型。

保留測試在本次固定執行中不參與調參，但無法證明過往研究者完全未見這段資料，故不自稱真正 pristine。資格門檻採至少 100 筆、95% Wilson 下界 ≥60%，並要求可稽核的 pristine 及前瞻驗證；本次一律未驗證。逐筆成功率也不因歷史樣本而獲保證。多策略、多幣、多週期存在多重比較偏差；保留所有結果，不挑最佳績效宣稱達標。

成本為每次 taker 費 .05%、滑價 .05%、每 8 小時雙向均扣 .03% 資金費的保守假設，非歷史實際費率。計畫 RR 先預留最長 14 日成本，不能拿最遠 TP2 單獨當整筆收益。TP1 後保護／2 ATR 追蹤停損只從下一棒生效；同棒停損優先，跳空用更差開盤成交。亦輸出 TP1 後掃保護停損情境，不能以最高理論路徑當確定報酬。雙倍成本與「所有止盈限價未成交」另列壓力情境。參與率限制使用過去成交額，並非委託簿成交保證。

## 風控與帳本

`risk.State` 的本金初始 10,000、準備金 1,000，與使用者自述 OKX 整體約 USD 1,000 分開；沒有 API 對帳，不把回測當真實餘額。紙上費用同時反映淨資金曲線及準備金耗用監控：準備金是費用預算警示，不是第二次扣帳、更不是實際隔離資產。

- 單筆初始上限 1,000，總未平倉計畫風險 ≤2,000，同策略 ≤2、總部位 ≤3；同標的避免重複持有。
- `single_cap` 僅用核實已實現專案本金：每完整增加 5,000 加 375，上限 2,000；下降撤回級距；未核實不調升。回測不提高真實風險級距。
- 初始本金或高水位回撤達 20%，或準備金 ≤500，持續停機；保存／載入後仍生效，沒有自動解鎖功能。
- 台北同日連虧兩筆停止新增。與兩筆均不同策略僅可回傳醒目的特例研究狀態，仍不得當成進場許可；第三筆再虧禁止第四筆。隔日只重評日內停機。
- `size` 按含成本止損、名義本金、保證金、最小單位縮倉；5／10／20 倍僅為紙上敏感度，**均未取得真實全倉安全認證**。100 倍直接拒絕。
- `cross_stress` 對全部持倉共同不利 20% 跳空，不假裝有逐倉或官方全倉強平價。止損預算非最大實損保證。

`ledger.Ledger` 僅由人工明確回覆建立成交：proposed → not_placed／pending_reconciliation → open → partially_closed／closed，或 cancelled。補齊時間、成交價量、成本、槓桿、止損止盈及 FX 來源才確認。可記錄多次部分進場（首次退出前、同計畫同 FX）、部分出場、資金費與出入金；已實現淨損益按部分數量分攤入場費，出入金不列交易獲利。`actual_confirmed`、`estimated_pending_reconciliation`、`paper_backtest` 嚴格分帳，支援 JSON 儲存。帳本成交價、成本及淨損益幣別為 USDT，估計餘額的輸入亦須 USDT，不能直接加到台幣本金；FX 附時間來源。估計餘額附來源、時間與待對帳標籤。尚未串接聊天收件或真實帳戶同步。

## 事件與人工報告

可選 `--events events.json`，格式為陣列，每項包括 `published_utc`、`event_utc`、`source`、`kind`（FED／US_ELECTION／QUADRUPLE_WITCHING／REGULATORY／PROJECT／OTHER），可加 `symbols`（完整合約 ID）、`major`、`direction`、`expected`。僅使用當時已公開資料。官方來源有主機名白名單；專案官方來源須由使用者先核實並標記 `official_source_verified: true`，不是程式自動認證。事件評估時間窗前後 24 小時只作研究門檻，重大事件保守移出紙上新進場。普通新聞空缺不加減勝率。輸出原始 UTC、台北時間、來源及「無法可靠量化」，不杜撰百分比；沒有完整歷史新聞流時明示覆蓋不足。

`EXAMPLE_REPORT.md` 是明確標記的模擬範例；價格非當下訊號，沒有虛構實際出場。最終下單由使用者親自決定。

# OKX 歷史回測研究版（v0.1）

**狀態：尚未取得真實歷史數據、尚未完成實績回測。請勿以此程式產生的策略作為槓桿下單依據。**

這個腳本是在原有的 Render `scanner.py` 以外新增的獨立回測工具，不會修改目前每30分鐘執行的 Render Cron，也不會送出任何交易訊號。

功能：透過 OKX `/api/v5/market/history-candles` 下載已確認的 30 分鐘 USDT 永續合約 K 線（以 `after` 向前分頁，最多 300 根／次），組合 1H、2H、4H、6H、8H、12H、1D；每天 K 線採 UTC+8 的開盤時間對齊；每30分鐘僅取當時已收盤的資料計算 BNF＋MACD 或多週期底背離，下一根30m開盤模擬進場。進出場包含費用、滑價、持有期間資金費率，若停損和停利在同一根觸及一律認定先停損。

預設先以 8 種流動性高的合約做 180 日探索性回測。這 **不是** 市值前200歷史成員的無偏測試；未能涵蓋價格缺口、真正歷史訂單簿、強平機制、逐時資金費率等風險，應把它視為先行可執行原型。統計須以足量不同市場條件、樣本外與步進式回測再驗證。策略 C 做空尚未完成建模。

## 研究者執行方式

在可連 OKX API 的環境：`pip install -r requirements.txt`，然後 `python historical_backtest.py --days 180 --output report.json`。必須透過 `python -m unittest -v tests.py` 檢驗回測工具。沒有 OKX 網路資料或測試未通過，不可以將結果標成完成。

建議下一階段至少一年多時段樣本，包含牛市／熊市／盤整，將資料依時間分割訓練、驗證、完全保留的樣本外測試。記錄樣本數、淨勝率、平均報酬、Profit Factor、最大回撤、持倉時間、各合約及各策略績效；設置「資料不足」而非補造勝率。

回測結果依據實際進場時可取得的流動性與費率應再調整。若你持續使用現有的 Render 掃描工作，它只掃市場行情且預設 `ENABLE_PUSH=false`／`RESEARCH_ACK=false`，直到正式驗證後再啟用研究提示。無需提供 OKX 交易 API key。

## 啟用訊號的最低驗收條件（先定門檻，不因結果而改）

- 核心訊號與實際 Render 掃描器的獨立對照測試通過，涵蓋 6H/12H/1D UTC+8 對齊與 8H 聚合、MACD pivot 3+3 確認，以及「下一根才成交」。
- 分別回報每套策略及逐合約的完整交易筆數；**樣本外少於100筆不能宣稱有可靠統計結果**。需要擴大樣本再驗證。
- 樣本外扣除合理費用後具正期望值、Profit Factor 高於1，並在加倍費用／滑價情境下仍可控；最大回撤與極端連虧可接受。以上僅是必要條件，不是獲利保證。
- 需真正持有逐日當時的可交易幣種與流動性資料以消除回看存活偏差，不能用今天的前200強說成過去前200。
- 在通過樣本外與實盤前瞻紙上測試前，正式訊號推播保持關閉。任何先行技術測試通知必須明確寫「測試，不是交易訊號」。
